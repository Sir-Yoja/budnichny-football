# Будничный футбол — повторно проверенные исправления приоритетов 1–3

Архив содержит папку `src` для замены одноимённой папки в проекте. Исправления направлены на согласованность статистики, единый расчёт рейтинга и проверку ввода. Коэффициенты рейтинга намеренно не калибровались и не менялись в этой версии.

## 1. Синхронизация матчевой и дневной статистики

- Статистика отдельного матча хранится в `game_player_stats`; итог игрового дня — в `game_day_players`.
- Агрегация суммирует голы, передачи, сейвы, пропущенные мячи и автоголы; признак игры в воротах сохраняется, если он отмечен хотя бы в одном матче.
- Перед синхронизацией проверяется, что игрок не привязан к разным командам в пределах одного игрового дня.
- Автоматическая синхронизация выполняется только после проверки полноты записей по всем матчам и участникам соответствующих команд.
- Если старые дневные итоги не совпадают с поматчевыми данными, они не заменяются молча: требуется явное подтверждение.
- Обычное редактирование сохраняет ID существующих матчей. Если меняется состав команд в уже заполненном матче, затронутая поматчевая статистика удаляется только после подтверждения; её нужно внести заново.
- Удаление матча пересчитывает дневные итоги только если исходная поматчевая статистика была полной и согласованной. Иначе дневные итоги сохраняются и показывается предупреждение.

## 2. Единый расчёт рейтинга

- Таблица, профиль и общий рейтинг используют `playerTotals`.
- Рейтинг отдельного игрового дня во всех разделах рассчитывается через `dayRatingForEntry`.
- Записи игрока дедуплицируются по игровому дню, чтобы повторные записи не завышали число дней и не увеличивали вес в среднем рейтинге.
- Принятые ранее коэффициенты в этой правке не изменялись.

## 3. Проверки ввода и ошибки сохранения

- Счёт и числовые показатели проверяются как целые неотрицательные значения до записи в базу.
- Пустые значения в редактируемых числовых полях сохраняются как пустые до проверки, а не превращаются незаметно в ноль.
- При расхождении суммы голов и автоголов со счётом отображается предупреждение. Сохранение можно отменить или явно подтвердить.
- Проверяется наличие двух разных существующих команд в каждом матче.
- Ошибки частичного сохранения сообщаются отдельно; интерфейс перечитывает данные перед следующей попыткой.
- При удалении дня изображение удаляется из хранилища после удаления записи дня из базы. Если очистка файла не удалась, показывается отдельное предупреждение.

## Проверки, выполненные при повторной проверке

- Архив ZIP проверен на целостность.
- Встроенный JavaScript в `legacyHtml.ts` декодирован и прошёл `node --check`.
- `App.tsx`, `legacyHtml.ts` и `main.tsx` прошли синтаксическую проверку через TypeScript `transpileModule` без диагностик.
- Локальный тест помощников с мокированным Supabase проверил суммирование статистики, обнаружение конфликтующих команд, защиту при несовпадающих дневных итогах, явную синхронизацию, а также определение полной и неполной матчевой статистики.

Полная production-сборка и интеграционные тесты с живым Supabase не выполнялись: архив содержит только `src` и не включает `package.json`, установленные зависимости или конфигурацию развертывания. Клиентская последовательность операций в разных таблицах не является транзакцией базы данных; при сетевой ошибке часть операций может успеть сохраниться. Перед публикацией сделайте резервную копию базы и проверьте проект в его обычном окружении.


## 4. Выпадающие списки места и команд

- Поле места при создании и редактировании игрового дня: «Металлург» или «Царицыно».
- Названия команд выбираются из фиксированного списка: «Пунктуальные», «Сообразительные», «Красивые», «Стильные».
- Цвет автоматически привязан к названию: белый `#FFFFFF`, тёмный `#383838`, красный `#E53935`, жёлтый `#FDD835`.
- Ручное изменение цвета отключено, чтобы цвет соответствовал названию команды.
